Deploying to Azure App Service

This guide covers deploying the Performance Problem Simulator to Azure App Service using GitHub Actions with OIDC authentication (no secrets required).

⚠️ Educational Use Only: This application intentionally creates performance problems. Deploy only to dedicated test/training environments, not production workloads.

Prerequisites

  • Azure subscription
  • GitHub repository with the simulator code
  • Azure CLI installed locally

Option 1: Automated Deployment with GitHub Actions

Step 1: Create Azure Resources

  1. Create Resource Group 
    az group create \
  --name rg-perf-simulator \
  --location eastus
  2. Create App Service Plan 
    az appservice plan create \
  --name plan-perf-simulator \
  --resource-group rg-perf-simulator \
  --is-linux \
  --sku B1
  3. Create Web App 
    az webapp create \
  --name app-perf-simulator-py \
  --resource-group rg-perf-simulator \
  --plan plan-perf-simulator \
  --runtime "PYTHON:3.14"

Step 2: Configure OIDC Authentication

ℹ️ OIDC (OpenID Connect) allows GitHub Actions to authenticate with Azure without storing secrets. This is more secure than using service principal credentials.
  1. Create Microsoft Entra ID App Registration 
    az ad app create --display-name "GitHub-PerfSimulator"
  2. Create Federated Credential 
    az ad app federated-credential create \
  --id <app-id> \
  --parameters '{
    "name": "github-main",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:<org>/<repo>:ref:refs/heads/main",
    "audiences": ["api://AzureADTokenExchange"]
  }'
  3. Assign Contributor Role 
    az role assignment create \
  --assignee <app-id> \
  --role Contributor \
  --scope /subscriptions/<sub-id>/resourceGroups/rg-perf-simulator

Step 3: Configure GitHub Repository

Add these variables to your repository (Settings → Secrets and Variables → Actions → Variables):

  • AZURE_CLIENT_ID - App registration client ID
  • AZURE_TENANT_ID - Your Azure AD tenant ID
  • AZURE_SUBSCRIPTION_ID - Your subscription ID
  • AZURE_WEBAPP_NAME - Name of your web app

Step 4: The Workflow File

The repository includes .github/workflows/deploy.yml:

.github/workflows/deploy.yml
name: Deploy to Azure

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  id-token: write
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.14'
      
      - name: Install dependencies
        run: pip install -r requirements.txt
      
      - name: Login to Azure
        uses: azure/login@v2
        with:
          client-id: ${{ vars.AZURE_CLIENT_ID }}
          tenant-id: ${{ vars.AZURE_TENANT_ID }}
          subscription-id: ${{ vars.AZURE_SUBSCRIPTION_ID }}
      
      - name: Deploy to App Service
        uses: azure/webapps-deploy@v3
        with:
          app-name: ${{ vars.AZURE_WEBAPP_NAME }}
          package: .

Option 2: Manual Deployment

Using Azure CLI

# Package the application
zip -r app.zip . -x "*.git*" -x "*__pycache__*" -x "*.pytest*"

# Deploy
az webapp deployment source config-zip \
  --resource-group rg-perf-simulator \
  --name app-perf-simulator-py \
  --src app.zip

Using Docker

# Build the image
docker build -t perfsim-py:latest .

# Tag for ACR
docker tag perfsim-py:latest myregistry.azurecr.io/perfsim-py:latest

# Push to ACR
az acr login --name myregistry
docker push myregistry.azurecr.io/perfsim-py:latest

# Update App Service
az webapp config container set \
  --name app-perf-simulator-py \
  --resource-group rg-perf-simulator \
  --docker-custom-image-name myregistry.azurecr.io/perfsim-py:latest

Post-Deployment Configuration

Configure Application Settings

az webapp config appsettings set \
  --name app-perf-simulator-py \
  --resource-group rg-perf-simulator \
  --settings \
    APP_ENV=production \
    LOG_LEVEL=INFO

Enable Application Insights

# Create Application Insights
az monitor app-insights component create \
  --app insights-perf-simulator \
  --location eastus \
  --resource-group rg-perf-simulator

# Get connection string and add to app settings
CONNECTION_STRING=$(az monitor app-insights component show \
  --app insights-perf-simulator \
  --resource-group rg-perf-simulator \
  --query connectionString -o tsv)

az webapp config appsettings set \
  --name app-perf-simulator-py \
  --resource-group rg-perf-simulator \
  --settings APPLICATIONINSIGHTS_CONNECTION_STRING=$CONNECTION_STRING

Configure Startup Command

az webapp config set \
  --name app-perf-simulator-py \
  --resource-group rg-perf-simulator \
  --startup-file "gunicorn -w 4 -k uvicorn.workers.UvicornWorker src.main:app"

Verifying the Deployment

  1. Check health endpoint 
    curl https://app-perf-simulator-py.azurewebsites.net/api/health
  2. Open the dashboard

    Navigate to https://app-perf-simulator-py.azurewebsites.net

  3. Test a simulation 
    curl -X POST https://app-perf-simulator-py.azurewebsites.net/api/cpu/start \
  -H "Content-Type: application/json" \
  -d '{"duration_seconds": 10, "workers": 1}'

Troubleshooting

Common Issues

  • 500 errors - Check Application Logs in Kudu
  • Container won't start - Verify Python version matches
  • Static files not served - Ensure whitenoise is configured
  • WebSocket fails - App Service supports WebSockets, ensure it's enabled

View Logs

# Stream logs
az webapp log tail \
  --name app-perf-simulator-py \
  --resource-group rg-perf-simulator

# Download logs
az webapp log download \
  --name app-perf-simulator-py \
  --resource-group rg-perf-simulator
