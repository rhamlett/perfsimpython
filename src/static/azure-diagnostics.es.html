☁️ Azure Guía de diagnóstico

Diagnosticar problemas de rendimiento en Azure App Service utilizando herramientas integradas y perfiles de Python

Referencia rápida: De Problem to Tool

Síntoma Herramienta primaria Herramientas secundarias
Alto uso de CPU App Service Diagnóstico → CPU Análisis py-spy, cPerfil
Crecimiento de la memoria Diagnosticar y resolver → análisis de memoria tracemalloc, memory_profiler
Respuestas lentas Application Insights → Rendimiento Registros de solicitudes, seguimiento de dependencias
Caídas de aplicaciones Diagnosticar y resolver → fallo del contenedor Registros de aplicaciones, registros stderr
HTTP 500 errores Application Insights → Fracasos Análisis de registros, App Service registros

Azure Portal: Diagnosticar y Resolver Problemas

Acceso a la herramienta

  1. Abre tu App Service en Azure Portal
  2. Clic "Diagnosticar y resolver problemas" En el menú izquierdo
  3. Selecciona una categoría de detector o utiliza la búsqueda

Detectores clave para el rendimiento

  • CPU Análisis- Identifica procesos y patrones de alta CPU
  • Análisis de memoria - Rastrea el uso de memoria y posibles fugas
  • Accidente de contenedor - Investiga por qué los contenedores se reinician
  • HTTP Errores del servidor - Analiza patrones de error 5xx
  • Aplicación web lenta - Identifica las causas de latencia

Application Insights

Preparando Application Insights

  1. Crear el recurso Application Insights — En el Azure Portal, busca Application Insights, clic + Create, elige tu suscripción, grupo de recursos, región y nombre, y luego haz clic Revisar + crear.
  2. Consigue la cadena de conexión — Una vez creado el recurso, ábrelo y accede a la Resumen Página. Copiar el Cadena de conexión mostrado cerca de la parte superior de la página.
  3. Añade la variable de entorno a tu App Service — En el Azure Portal, navega a tu App Service, ve a Ajustes > variables de entorno, y añadir una nueva configuración de aplicación con el nombre APPLICATIONINSIGHTS_CONNECTION_STRING y pegar la cadena de conexión como valor. Clic Solicita y confirmar el reinicio.

Características principales

  • Rendimiento - Duración de la solicitud, llamadas de dependencia, tiempos de respuesta
  • Fracasos - Seguimiento de excepciones, solicitudes fallidas, tasas de error
  • Métricas en vivo - Monitorización del rendimiento en tiempo real
  • Mapa de aplicaciones - Grafo de dependencias visuales

💡 Propina: Utiliza la función de Búsqueda de Transacciones en Application Insights para rastrear solicitudes específicas de extremo a extremo, incluyendo todas las llamadas de dependencia y su sincronización.

🔗 Correlación ID de simulación

A cada instancia de simulación se le asigna una única ID de simulación (GUID) que permite una correlación extrema a extrema entre la interfaz del panel de control y los diagnósticos Azure .

Encontrar identificadores de simulación

En el panel de control: Pasa el cursor sobre cualquier mensaje relacionado con la simulación en el Registro de Eventos (marcado con un subrayado punteado) para ver el ID completo de la simulación en una descripción emergente.

En Azure: El mismo ID de simulación se emite en los registros del lado del servidor y puede encontrarse en:

  • Application Insights - Trazas de búsqueda y eventos personalizados por ID de simulación
  • Análisis de registros - Registros de consulta usando el ID como filtro
  • Contenedor/App Service troncos - Filtrar stdout/stderr por el GUID

Consultas de correlación

Utiliza estas consultas KQL en Log Analytics para correlacionar eventos del panel con la telemetría del servidor:

⚠️ Diferencias en los nombres de las tablas: Los espacios de trabajo de Log Analytics utilizan nombres de tablas y columnas diferentes a los Application Insightsclásicos. Si ves errores como "El nombre 'traces' no se refiere a ninguna tabla conocida", utiliza los nombres de Log Analytics que aparecen a continuación:

// Find simulation start/end events by Simulation ID
AppEvents
| where Name in ("SimulationStarted", "SimulationEnded")
| where Properties["SimulationId"] == "YOUR-SIMULATION-ID-HERE"
| project TimeGenerated, Name, Properties
| order by TimeGenerated asc
// Find all requests during a simulation time window
let simStart = toscalar(
    AppEvents 
    | where Name == "SimulationStarted" and Properties["SimulationId"] == "YOUR-SIMULATION-ID-HERE"
    | project TimeGenerated);
let simEnd = toscalar(
    AppEvents 
    | where Name == "SimulationEnded" and Properties["SimulationId"] == "YOUR-SIMULATION-ID-HERE"
    | project TimeGenerated);
AppRequests
| where TimeGenerated between (simStart .. simEnd)
| order by TimeGenerated asc
// Find failed requests during a simulation
let simId = "YOUR-SIMULATION-ID-HERE";
let simEvents = AppEvents | where Properties["SimulationId"] == simId;
let simStart = toscalar(simEvents | where Name == "SimulationStarted" | project TimeGenerated);
let simEnd = toscalar(simEvents | where Name == "SimulationEnded" | project TimeGenerated);
AppRequests
| where TimeGenerated between (simStart .. simEnd)
| where Success == false
| project TimeGenerated, Name, ResultCode, DurationMs, Url
| order by TimeGenerated asc

Flujo de trabajo de resolución de problemas

  1. Inicia una simulación desde el panel de control
  2. Pasa el cursor sobre el mensaje de inicio en el Registro de Eventos para copiar el ID de Simulación
  3. Portal abierto Azure → Application Insights → Registros (o Análisis de Registros)
  4. Consulta los registros usando el ID de simulación para ver toda la actividad relacionada del lado del servidor
  5. Correlacionar las marcas de tiempo entre eventos del panel de control y métricas del servidor

💡 Propina: El ID de Simulación ayuda a aislar la telemetría al ejecutar múltiples simulaciones simultáneas o cuando el panel de control es utilizado por varios usuarios.

Kudu Console (Diagnóstico Avanzado)

Acceso a Kudu

  1. Ve a tu App Service
  2. Clic Herramientas avanzadas → Ve
  3. O navegar hacia https://<app-name>.scm.azurewebsites.net

Acceso SSH

Para App Servicede Linux, utiliza SSH para acceder al contenedor:

# From Kudu: Debug console → SSH
# Or use Azure CLI:
az webapp ssh --name <app-name> --resource-group <rg>

Comandos SSH útiles

# View running processes
top -bn1

# Memory usage
free -m

# List Python processes
ps aux | grep python

# View application logs
tail -f /home/LogFiles/docker/*.log

Herramientas de perfilado en Python

py-spy (Perfilador de muestreo)

Lo mejor para perfilar CPU en producción sin modificar código:

# Install in SSH session
pip install py-spy

# Profile running process
py-spy top --pid <python-pid>

# Record flame graph
py-spy record -o profile.svg --pid <python-pid>

cProfile (perfilador integrado)

Añadir perfilado a puntos finales específicos:

import cProfile
import pstats
import io

@app.get("/api/debug/profile")
async def profile_endpoint():
    pr = cProfile.Profile()
    pr.enable()
    
    # Your code here
    
    pr.disable()
    s = io.StringIO()
    pstats.Stats(pr, stream=s).sort_stats('cumulative')
    return {"profile": s.getvalue()}

tracemalloc (Rastreo de memoria)

Rastrear las asignaciones de memoria:

import tracemalloc

tracemalloc.start()

# Your code here

snapshot = tracemalloc.take_snapshot()
top_stats = snapshot.statistics('lineno')

for stat in top_stats[:10]:
    print(stat)

Consultas de Análisis de Registros (KQL)

Consultas Comunes

Encuentra solicitudes lentas:

requests
| where duration > 5000
| project timestamp, name, duration, resultCode
| order by duration desc

Tasa de error por punto final:

requests
| where success == false
| summarize count() by name
| order by count_ desc

Reinicios de contenedores:

ContainerAppSystemLogs_CL
| where Log_s contains "exited"
| project TimeGenerated, Log_s

Diagnóstico específico de simulación

CPU Estrés

Cuando CPU estrés está activo, observa:

  • Métricas → CPU aumento porcentual
  • Diagnóstico → CPU Análisis muestra los procesos de los trabajadores
  • Py-Spy muestra bucles cerrados en las funciones de cálculo

Presión de memoria

Cuando se asigna memoria:

  • Métricas → Aumento del porcentaje de memoria
  • El diagnóstico → análisis de memoria muestra crecimiento del proceso
  • Tracemalloc muestra grandes asignaciones de bytearrays

Operaciones de bloqueo

Cuando el bloqueo está activo:

  • App Insights → Rendimiento muestra un aumento en los tiempos de respuesta
  • Métricas en Vivo muestra la cola de solicitudes
  • Agotamiento del pool de hilos visible en las estadísticas del proceso

Fallos de aplicaciones

Después de provocar un fallo:

  • Los registros de contenedores muestran el código de salida (137=OOM, 134=SIGABRT)
  • App Insights → Fallos muestra excepciones no gestionadas
  • El registro de actividad muestra los eventos de reinicio de contenedores
