☁️ Azure 诊断指南

使用内置工具和 Python 性能分析器诊断 Azure App Service 性能问题

快速参考：问题到工具

症状 主要工具 次级工具
高 CPU 使用率 App Service 诊断→ CPU 分析 py-spy，cProfile
记忆增长 诊断与解决→记忆分析 特雷斯马洛克，memory_profiler
反应缓慢 Application Insights → 表演 请求日志，依赖跟踪
应用程序崩溃 诊断并解决→集装箱崩溃 应用日志，stderr 日志
HTTP 500 个错误 Application Insights → 失败 日志分析， App Service 日志

Azure 门户：诊断与解决问题

访问该工具

  1. 打开Azure传送门中的App Service
  2. 咔哒 “诊断并解决问题” 在左侧菜单中
  3. 选择探测器类别或使用搜索

性能关键探测器

  • CPU 分析 - 识别高 CPU 过程和模式
  • 记忆分析 - 跟踪内存使用和潜在泄漏
  • 集装箱坠毁 - 调查容器重启的原因
  • HTTP 服务器错误 - 分析5xx错误模式
  • 网页应用缓慢 - 识别延迟原因

Application Insights

Application Insights的建立

  1. 创建 Application Insights 资源 ——在 Azure 门户中，搜索 Application Insights，咔嗒 + 创作，选择你的订阅、资源组、地区和名称，然后点击 审核 + 创建.
  2. 拿连接线 —— 资源创建后，打开它并前往 概述 侍从。复制 连接串 显示在页面顶部附近。
  3. 把环境变量加到你的 App Service ——在 Azure 门户，导航到你的 App Service，前往 设置>环境变量，并添加一个名为 的新应用设置 APPLICATIONINSIGHTS_CONNECTION_STRING 并将连接字符串作为值粘贴。咔哒 申请 并确认重启。

主要特征

  • 性能 - 请求时长、依赖调用、响应时间
  • 故障 - 异常跟踪、请求失败、错误率
  • 实时指标 - 实时性能监控
  • 应用地图 - 视觉依赖图

💡 提示： 使用 Application Insights 中的事务搜索功能，从端到端追踪特定请求，包括所有依赖调用及其时序。

🔗 仿真ID相关性

每个仿真实例都被赋予唯一 仿真ID （GUID）实现仪表盘界面与 Azure 诊断之间的端到端关联。

寻找仿真ID

在仪表盘中： 将鼠标悬停在事件日志中任何与仿真相关的消息（标记为 虚线下划线）以便在提示中查看完整的模拟ID。

Azure： 相同的仿真ID也出现在服务器端日志中，并可在以下格式中找到：

  • Application Insights - 通过仿真ID搜索跟踪和自定义事件
  • 日志分析 - 使用ID作为过滤器的查询日志
  • 容器/App Service 日志- 按 标准/标准GUID 过滤

相关性查询

在Log Analytics中使用这些KQL查询，将仪表盘事件与服务器遥测数据关联起来：

⚠️ 表格名称差异： Log Analytics 工作区使用与经典 Application Insights不同的表和列名。如果你看到像这样的错误 “'traces'这个名称并不指任何已知的表格”，请使用下面的Log Analytics名称：

经典 Application Insights 日志分析工作区
tracesAppTraces
customEventsAppEvents
requestsAppRequests
exceptionsAppExceptions
dependenciesAppDependencies
messageMessage
timestampTimeGenerated
customDimensionsProperties
 
// Find simulation start/end events by Simulation ID
AppEvents
| where Name in ("SimulationStarted", "SimulationEnded")
| where Properties["SimulationId"] == "YOUR-SIMULATION-ID-HERE"
| project TimeGenerated, Name, Properties
| order by TimeGenerated asc
// Find all requests during a simulation time window
let simStart = toscalar(
    AppEvents 
    | where Name == "SimulationStarted" and Properties["SimulationId"] == "YOUR-SIMULATION-ID-HERE"
    | project TimeGenerated);
let simEnd = toscalar(
    AppEvents 
    | where Name == "SimulationEnded" and Properties["SimulationId"] == "YOUR-SIMULATION-ID-HERE"
    | project TimeGenerated);
AppRequests
| where TimeGenerated between (simStart .. simEnd)
| order by TimeGenerated asc
// Find failed requests during a simulation
let simId = "YOUR-SIMULATION-ID-HERE";
let simEvents = AppEvents | where Properties["SimulationId"] == simId;
let simStart = toscalar(simEvents | where Name == "SimulationStarted" | project TimeGenerated);
let simEnd = toscalar(simEvents | where Name == "SimulationEnded" | project TimeGenerated);
AppRequests
| where TimeGenerated between (simStart .. simEnd)
| where Success == false
| project TimeGenerated, Name, ResultCode, DurationMs, Url
| order by TimeGenerated asc

故障排除工作流程

  1. 从仪表盘开始模拟
  2. 将鼠标悬停在事件日志中的开始消息上，复制模拟ID
  3. 打开 Azure 门户→ Application Insights →日志（或日志分析）
  4. 使用仿真ID查询日志，查看所有相关的服务器端活动
  5. 将仪表盘事件与服务器指标的时间戳关联起来

💡 提示： 当多个并发模拟运行或仪表盘被多个用户使用时，模拟ID有助于隔离遥测数据。

Python 分析工具

py-spy（采样分析器）

最适合在生产环境中进行 CPU 配置文件而不修改代码：

# Install in SSH session
pip install py-spy

# Profile running process
py-spy top --pid <python-pid>

# Record flame graph
py-spy record -o profile.svg --pid <python-pid>

cProfile（内置分析器）

为具体端点添加画像：

import cProfile
import pstats
import io

@app.get("/api/debug/profile")
async def profile_endpoint():
    pr = cProfile.Profile()
    pr.enable()
    
    # Your code here
    
    pr.disable()
    s = io.StringIO()
    pstats.Stats(pr, stream=s).sort_stats('cumulative')
    return {"profile": s.getvalue()}

tracemalloc（记忆追踪）

跟踪内存分配：

import tracemalloc

tracemalloc.start()

# Your code here

snapshot = tracemalloc.take_snapshot()
top_stats = snapshot.statistics('lineno')

for stat in top_stats[:10]:
    print(stat)

日志分析查询（KQL）

常见查询

寻找慢节奏请求：

requests
| where duration > 5000
| project timestamp, name, duration, resultCode
| order by duration desc

按终点分类的错误率：

requests
| where success == false
| summarize count() by name
| order by count_ desc

容器重启：

ContainerAppSystemLogs_CL
| where Log_s contains "exited"
| project TimeGenerated, Log_s

仿真专用诊断

CPU 压力

当 CPU 压力活跃时，注意：

  • 指标→ CPU 百分比激增
  • 诊断→ CPU 分析显示了工人流程
  • py-spi 显示计算函数中的紧密循环

记忆压力

内存分配时：

  • 指标→内存百分比增加
  • 诊断→记忆分析显示进程增长
  • tracemalloc显示了大量的bytearray分配

阻断行动

阻挡激活时：

  • 应用洞察→性能显示响应时间有所提升
  • 实时指标显示请求排队
  • 进程统计中可见线程池耗尽

应用程序崩溃

触发崩溃后：

  • 容器日志显示出口代码（137=OOM，134=SIGABRT）
  • App Insights → Failures 显示未处理的异常
  • 活动日志显示容器重启事件
